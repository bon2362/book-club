# Timeline — ленты времени

Раздел позволяет владельцу проекта собирать исторические таймлайны и делиться
каждым по публичной ссылке. Перенесён из локального десктопного приложения
`~/documents/timeline` (React + Fastify + SQLite).

  `docs/superpowers/plans/2026-07-31-timeline-stage-2-schema-import.md`

## Модель данных

Таймлайн — не собственный набор событий, а **подборка**: событие заводится один
раз в общем справочнике и включается в несколько таймлайнов, где у него могут
быть своя заметка и оформление.

| Таблица | Назначение |
|---|---|
| `historical_event_types` | Тип события: название, цвет, иконка |
| `historical_events` | Событие: название, тип, даты, описание, картинка |
| `historical_epochs` | Эпоха: название, период, описание, картинка |
| `timelines` | Подборка: название, `slug`, `published`, сохранённый вид |
| `timeline_events` | Связь таймлайн↔событие + заметка |
| `timeline_epochs` | Связь таймлайн↔эпоха + цвет, видимость, дорожка |

Все шесть таблиц под аудитом: зарегистрированы в `lib/audit/audited-tables.ts`,
триггеры создаёт `drizzle/0056_timeline_tables.sql`.

**Даты исторические.** Год + эра (`BCE`/`CE`), месяц и день опциональны. У
события конец может отсутствовать (точка), быть задан (интервал) или
заменяться признаком `ongoing`. Ограничения на уровне БД запрещают год ≤ 0,
день без месяца, неполный конец интервала и сочетание `ongoing` с датой конца.

## Код

```
lib/timeline/
  historical-date.ts        арифметика дат: эры, сравнение, валидация
  calendar-year-overlap.ts  пересечение периодов по календарным годам
  types.ts                  TimelineEventDates — даты события для геометрии
  index.ts                  единая точка входа
  geometry/                 расчёт раскладки ленты (9 модулей, чистые функции)
  import/                   одноразовый код переноса
    html-to-markdown.ts     конвертер под теги Tiptap
    export-shape.ts         zod-схемы JSON-выгрузки
    map-records.ts          строки SQLite → строки Postgres
scripts/
  timeline-export.cjs       SQLite → JSON (запускается из проекта-источника)
  timeline-import.ts        JSON → Postgres
```

`geometry/` не знает ни про базу, ни про React — это чистые функции над числами
и датами, покрытые тестами. `import/` можно удалить после того, как перенос
окончательно закрыт.

## Перенос данных

Выполняется один раз на базу. Скрипт импорта **отказывается работать**, если
целевые таблицы не пусты, — защита от повторного прогона.

```bash
# 1. Выгрузка из локального SQLite (better-sqlite3 есть только там)
cd ~/documents/timeline
NODE_PATH="$PWD/node_modules" node <путь-к-book-club>/scripts/timeline-export.cjs \
  data/timeline.sqlite > /tmp/timeline-export.json

# 2. Миграция и импорт
node --env-file=<env-файл> scripts/apply-migration.mjs drizzle/0056_timeline_tables.sql
npx tsx --env-file=<env-файл> scripts/timeline-import.ts /tmp/timeline-export.json
```

`tsx` не входит в зависимости проекта — запуск только через `npx tsx`.
Vercel миграции не применяет: по продовой базе они выполняются вручную.

Slug переносимых таймлайнов задан явной таблицей `SLUG_BY_TITLE` в скрипте
импорта. Новый таймлайн без записи в ней вызовет ошибку с его названием —
дополнить таблицу или задать slug вручную после этапа 4.

## Конвертация описаний

Редактор Tiptap хранил HTML; в базе лежит markdown. Конвертер поддерживает
ровно те теги, что встречались в данных: `p`, `a`, `strong`, `ul`, `li`, `br`.
**На любом другом теге он падает** — при разовом переносе молча потерянный
фрагмент текста обнаружился бы нескоро.

Символ `_` намеренно не экранируется: внутри слова он не создаёт выделения по
CommonMark, а адреса ссылок содержат его часто.
