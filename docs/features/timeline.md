# Timeline — ленты времени

Раздел позволяет владельцу проекта собирать исторические таймлайны и делиться
каждым по публичной ссылке. Перенесён из локального десктопного приложения
`~/documents/timeline` (React + Fastify + SQLite).

- **Спецификация:** `docs/superpowers/specs/2026-07-31-timeline-section-design.md`
- **Планы этапов:** `docs/superpowers/plans/2026-07-31-timeline-stage-0-1-core.md`,
  `docs/superpowers/plans/2026-07-31-timeline-stage-2-schema-import.md`,
  `docs/superpowers/plans/2026-07-31-timeline-stage-4-admin.md`

## Маршруты

| Маршрут | Что делает |
|---|---|
| `/timeline` | Список лент. Обычному посетителю — только `published = true`, админу ещё и черновики с пометкой |
| `/timeline/[slug]` | Лента времени. `notFound()`, если ленты нет либо она черновик, а смотрит не админ |

### Админские маршруты

Все восемь начинаются с `auth()` + `session.user.isAdmin` (иначе `403`), несут
`export const dynamic = 'force-dynamic'` и мутируют только внутри
`withAuditContext({ source: 'admin' })`.

| Маршрут | Методы | Особенности |
|---|---|---|
| `/api/admin/timeline/event-types` | `GET`, `POST` | `GET` отдаёт `usageCount` — число событий типа. Повтор названия → `409` |
| `/api/admin/timeline/event-types/[id]` | `PATCH`, `DELETE` | `DELETE` считает события типа и при ненулевом отвечает `409` «Тип используется в N событиях»: внешний ключ стоит `ON DELETE RESTRICT`, без проверки был бы `500` |
| `/api/admin/timeline/events` | `GET`, `POST` | `POST` проверяет существование типа (`400`) |
| `/api/admin/timeline/events/[id]` | `PATCH`, `DELETE` | Удаление события каскадом снимает его со всех лент |
| `/api/admin/timeline/epochs` | `GET`, `POST` | |
| `/api/admin/timeline/epochs/[id]` | `PATCH`, `DELETE` | |
| `/api/admin/timeline/timelines` | `GET` | Список с черновиками (`includeUnpublished`) |
| `/api/admin/timeline/timelines/[id]` | `PATCH` | Принимает **только** `{ published: boolean }`; лишнее поле → `400` |

### Проверка данных

`lib/timeline/admin.ts` — схемы zod и две функции проверки дат
(`assertEventDates`, `assertEpochDates`), бросающие `TimelineValidationError`
с русским текстом. Их зовут и маршрут, и форма: форма отвечает мгновенно,
маршрут не полагается на форму. Правила повторяют ограничения миграции `0056`:

- год строго больше нуля, эра `BCE` или `CE`;
- день задаётся только вместе с месяцем;
- у события конец либо задан полностью, либо отсутствует целиком;
- `ongoing` несовместим с датой окончания;
- у эпохи конец обязателен;
- начало не позже конца — сравнение через `compareHistoricalDates`, **не
  числами**: «50 до н. э. → 100 до н. э.» по числам выглядит возрастающим;
- цвет — семь символов `#RRGGBB`.

Обе страницы — серверные компоненты с `export const dynamic = 'force-dynamic'`:
без него Next закэшировал бы их на сборке. У страницы ленты есть
`generateMetadata` — раздел существует ради того, чтобы делиться ссылкой.

## Модель данных

Таймлайн — не собственный набор событий, а **подборка**: событие заводится один
раз в общем справочнике и включается в несколько таймлайнов, где у него могут
быть своя заметка и оформление.

| Таблица | Назначение |
|---|---|
| `historical_event_types` | Тип события: название, цвет, иконка |
| `historical_events` | Событие: название, тип, даты, описание, картинка |
| `historical_epochs` | Эпоха: название, период, описание, картинка |
| `timelines` | Подборка: название, `slug`, `published`, сохранённый вид |
| `timeline_events` | Связь таймлайн↔событие + заметка и локальный флаг `visible` |
| `timeline_epochs` | Связь таймлайн↔эпоха + цвет, видимость, дорожка |

Все шесть таблиц под аудитом: зарегистрированы в `lib/audit/audited-tables.ts`,
триггеры создаёт `drizzle/0056_timeline_tables.sql`.

Колонку `timeline_events.visible boolean default true not null` добавляет
`drizzle/0058_timeline_event_hidden.sql`. Триггер таблицы уже существовал,
поэтому новая колонка автоматически входит в `before`/`after` аудита.

## Правка на полотне

Администратор редактирует выбранное событие или эпоху прямо в карточке над
полотном. `TimelineInlineEditor.tsx` намеренно отправляет две независимые
мутации:

- общие поля (`title`, даты, тип, описание, `imageUrl`, `imageCaption`) — в
  `PATCH /api/admin/timeline/events/[id]` или `/epochs/[id]`; изменение видно
  во всех лентах;
- свойства связи с текущей лентой — в `PUT/PATCH
  /api/admin/timeline/timelines/[id]/events/[eventId]` или соответствующий
  маршрут эпохи. Сюда относятся заметка, `visible`, а для эпохи также цвет и
  закреплённая дорожка.

Подпись этой границы всегда видна в редакторе. Открепление вызывает `DELETE`
маршрута связи и не удаляет общую запись. Удаление из общей базы — отдельное
действие с инлайн-подтверждением. Картинка задаётся только внешним адресом;
загрузки файла нет.

Кнопки «+ Событие» и «+ Эпоха» открывают форму на месте карточки. Начальный год
берётся из середины текущего viewport, для эпохи конец подставляется через 50
лет. После `POST` форма берёт идентификатор из `{ success, data: { id } }` и
сразу создаёт связь с открытой лентой. `⌘/Ctrl+Enter` отправляет форму, `Esc`
отменяет.

### Сокращённая админская вкладка

`AdminTimelinePanel.tsx` загружает только два справочника: типы событий и
ленты. Во вкладке остаются создание/правка типов, создание/правка/удаление
лент, публикация и ссылка на публичную страницу. Формы событий и эпох и экран
состава из вкладки убраны: эти операции выполняются на `/timeline/[slug]`.

API событий, эпох и связей при этом остаётся — его использует редактор на
полотне. Название ленты в админском списке больше не открывает отдельный экран
состава.

### Общая база и граница публичных данных

`fetchTimelineBySlug(slug, { includeLibrary })` возвращает непривязанные
`libraryEvents`/`libraryEpochs` только при `includeLibrary: true`. Значение
ставит серверная страница из `session.user.isAdmin`; query-параметра для него
нет. Для гостя дополнительные запросы к справочникам вообще не выполняются,
поэтому названия «призраков» отсутствуют и в HTML/RSC-ответе, а не просто
скрыты CSS.

Админу чип «Вся база» рисует непривязанные элементы полупрозрачно; поиск
помечает их «+ прикрепить». Клик открывает обычную карточку с отдельной кнопкой
прикрепления и до клика базу не меняет. Локальный фильтр и состояние «Вся база»
после reload сбрасываются и в БД не сохраняются.

**Даты исторические.** Год + эра (`BCE`/`CE`), месяц и день опциональны. У
события конец может отсутствовать (точка), быть задан (интервал) или
заменяться признаком `ongoing`. Ограничения на уровне БД запрещают год ≤ 0,
день без месяца, неполный конец интервала и сочетание `ongoing` с датой конца.

цвета эпох детерминированно переводятся в утверждённую палитру светлых тинтов.

### Устойчивость подписей

Положение подписи события задают только его дата и текущий масштаб. Раскладка
получает полный набор событий до фильтрации и отсечения по краям, а подписи
всегда идут вправо от своей даты. Панорамирование, выбор элемента, фильтры типов,
«Вся база» и переключатель эпох не меняют дорожки. Призраки общей базы
размещаются после прикреплённых элементов, поэтому не могут их сдвинуть.

Подпись у правого края намеренно обрезается полотном. Это принятое владельцем
поведение: перенос подписи влево сохранил бы её целиком, но заставил бы её
перескакивать через точку при прокрутке.

Цена устойчивости — свободные места в дорожках после скрытия событий фильтром
не переиспользуются. При выключенных эпохах их полосы исчезают, но строка эпох
сохраняет рассчитанную по полному набору высоту, поэтому под осью остаётся
пустая полоса. Масштаб — единственное действие, которое вправе переложить
события заново.

Переключение «лента ↔ список» сделано CSS-классами (`hidden md:block` и
`md:hidden`), а не определением ширины в JS: серверный рендер не знает ширину
экрана, и хук расходился бы с разметкой при гидратации.

Не переносились из исходного приложения: изменение границ интервала мышью,
перетаскивание дорожек эпох, разделитель панелей и отмена действия. Фильтры
типов и эпох доступны в постоянной легенде; их начальное состояние берётся из
`filter_type_ids` и `epochs_visible`, а изменения живут только до перезагрузки
страницы и в базу не записываются.

**Палитра.** `components/nd/timeline/admin/palette.ts` — единственное место
админки с сырым hex, и это осознанно: значение уезжает в колонку
`historical_event_types.color` и приходит обратно как данные. Токен `var(--…)`
в базу положить нельзя — на сервере его некому раскрыть. В разметке цветов
по-прежнему нет, поэтому `scripts/check-no-raw-hex.sh` остаётся зелёным.

**Вкладка не повторяет редактор полотна.** События, эпохи и состав ленты
редактируются только на `/timeline/[slug]`; в админке остаются типы событий и
операции над самими лентами.

**E2E:** `e2e/timeline.spec.ts` (открытие по ссылке, выбор события, локальная
легенда, черновик и 404), `e2e/timeline-layout.spec.ts` (наложение подписей до

## Перенос данных

Выполняется один раз на базу. Скрипт импорта **отказывается работать**, если
целевые таблицы не пусты, — защита от повторного прогона.

```bash
# 1. Выгрузка из локального SQLite (better-sqlite3 есть только там)
cd ~/documents/timeline
NODE_PATH="$PWD/node_modules" node <путь-к-book-club>/scripts/timeline-export.cjs \
  data/timeline.sqlite > /tmp/timeline-export.json

# 2. Миграция и импорт
node --env-file=<env-файл> scripts/apply-migration.mjs drizzle/0056_timeline_tables.sql
npx tsx --env-file=<env-файл> scripts/timeline-import.ts /tmp/timeline-export.json
```

`tsx` не входит в зависимости проекта — запуск только через `npx tsx`.
Vercel миграции не применяет: по продовой базе они выполняются вручную.

Slug переносимых таймлайнов задан явной таблицей `SLUG_BY_TITLE` в скрипте
импорта. Новый таймлайн без записи в ней вызовет ошибку с его названием —
дополнить таблицу или задать slug вручную после этапа 4.

Перенесено на 31.07.2026: 3 типа, 31 событие, 14 эпох, 2 таймлайна,
36 связей с событиями, 15 связей с эпохами.

## Начальный вид публичной страницы

Сохранённый `viewport_start`/`viewport_end` используется, только если внутри
него находится не меньше `max(5, ceil(25% × общее число элементов))` событий
и эпох. Иначе страница открывается в режиме «Вместить всё». Поэтому старый
диапазон «Всеобщей истории» с 4 из 31 событий отвергается, но осмысленный
авторский стартовый кадр сохраняется.

## Визуальный язык и раскладка

Полотно занимает всю ширину окна, остаётся плоской частью страницы без рамки и
белой карточки. Для него используются токены `--tl-*`; цвета данных зеркалят
`--data-*`, а светлые полосы эпох — `--tint-*`. Сами сохраняемые значения
палитры находятся в `components/nd/timeline/admin/palette.ts`; raw hex в этом
файле — данные для БД, а не оформление компонента.

Точечное событие деградирует строго по цепочке **подпись → точка → кластер** и
не исчезает. У правого края подпись отражается влево без многоточия. Интервал
не исчезает даже при нехватке дорожек: сначала теряет подпись, затем попадает
на наименее занятую дорожку. Подпись интервала привязана к его полосе: у
правого края растёт влево от начала, а если вся полоса за пределами полотна —
не рисуется, чтобы дата не оказалась над чужим участком шкалы.

Обычное колесо панорамирует горизонтально, Ctrl/⌘ + колесо масштабирует под
курсором, предел диапазона — от 2 до 40 000 лет. Выбор видимой метки диапазон
не меняет; невидимая сдвигает его минимально до поля 80 px. `Esc` снимает
выбор. Перетаскивание начинается после 3 px и не превращается в клик.

## Конвертация описаний

Редактор Tiptap хранил HTML; в базе лежит markdown. Конвертер поддерживает
ровно те теги, что встречались в данных: `p`, `a`, `strong`, `ul`, `li`, `br`.
**На любом другом теге он падает** — при разовом переносе молча потерянный

CommonMark, а адреса ссылок содержат его часто.
