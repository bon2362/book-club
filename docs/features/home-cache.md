# Кэш данных главной

## Зачем

Главная (`app/page.tsx`) помечена `force-dynamic` и раньше при каждом заходе
делала больше десятка запросов к Postgres. Большую часть трафика на главную
дают боты (TernCrawler, Googlebot, SEO-сканеры), они ходят и ночью. Neon
засыпает только после 5 минут тишины, поэтому база почти не спала: около
2.8 CU-час в день (разбор от 2026-11-09).

После фикса анонимный заход не обращается к базе вообще.

## Как устроено

- **Общие данные** (каталог со счётчиками записей и саммари, описания тегов,
  опубликованное интро, открытая сессия подбора, настройка блока подборок,
  опубликованные подборки) читаются через `unstable_cache` в
  `lib/cache/home-public-data.ts`. Каждая часть — отдельная запись кэша
  (лимит Vercel Data Cache — 2 МБ на запись).
- **Персональные данные** запрашиваются только для залогиненного пользователя:
  `getSignupForUser(userId)` вместо прежнего `getAllSignups()`, который на
  каждый заход тянул всех записавшихся с контактами.
- `auth()` для анонима базу не трогает (JWT-стратегия). Для залогиненного
  колбэк `jwt` делает 1–3 запроса в `users` — это вне рамок этого кэша.

## Сброс

- Все записи помечены меткой `HOME_PUBLIC_TAG` (`lib/cache/home-public-tag.ts`).
- `withAuditContext` вызывает `invalidateHomePublicCache()` после **каждой**
  успешной транзакции. Все мутации и так обязаны идти через эту обёртку
  (ESLint), поэтому сброс не нужно расставлять в каждом роуте — новые роуты
  получают его автоматически. После отката транзакции сброса нет.
- Вне запроса Next.js (скрипты, Jest) `revalidateTag` бросает исключение —
  оно глушится, там кэша нет.
- **Страховочный срок — 1 час** (`HOME_PUBLIC_REVALIDATE_SECONDS`). Он нужен
  для мутаций мимо обёртки: ESLint ловит только `db.insert/update/delete`
  по имени `db`, а хелперы с параметром `dbClient = db` по умолчанию или
  сырые `db.execute(sql\`update …\`)` проходят мимо. Такая правка появится на
  главной не позже чем через час. Короче срок не делать: unstable_cache
  обновляет просроченную запись по первому запросу, и боты снова будут
  будить базу.

## Тестовый режим

При `NEXTAUTH_TEST_MODE=true` кэш выключен — функции идут в базу напрямую.
E2E часто пишут в базу SQL-запросами в обход приложения (`dbExec`,
`e2e/fixtures.ts`), и закэшированная главная показывала бы им устаревшие
данные. Следствие: **E2E кэш не проверяют**. Проверки кэша — unit-тесты
`lib/cache/*.test.ts` и `lib/audit/with-audit-context.test.ts`.

## Если данные на главной не обновились

1. Правка прошла через `withAuditContext`? Если нет — обернуть (это и так
   требование аудита, см. `docs/features/audit-log.md`).
2. Подождать час — сработает страховочный срок.
3. Новый деплой меняет ключи кэша (в ключ входит код функции), так что
   после деплоя изменённого загрузчика кэш фактически новый.
