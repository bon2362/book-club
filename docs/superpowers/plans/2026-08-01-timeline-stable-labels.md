# Лента времени: подписи не прыгают

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подпись события стоит на одном месте относительно своей даты и не
двигается ни при панорамировании, ни при переключении фильтров. Единственное
действие, которое имеет право переложить ленту заново, — изменение масштаба.

**Architecture:** Меняется не отрисовка, а **основание раскладки**. Сейчас
дорожки считаются по тому набору, который дошёл до слоя после фильтров и
отсечения по краям, а сторона подписи выбирается по текущему положению точки на
экране. И то и другое — функции прокрутки, отсюда прыжки. После правки раскладка
считается по полному набору элементов ленты и не знает, что именно сейчас видно;
видимость решается только на отрисовке.

**Tech Stack:** TypeScript, React 18, Jest, Playwright.

## Решение владельца, из которого всё следует

Подпись, не поместившаяся до правого края, **обрезается краем полотна** — это
желаемое поведение, а не дефект. Альтернатива (двигать подпись, чтобы она
оставалась видимой) отвергнута: подписи начинают скакать при прокрутке.

Из этого следует правило, которому подчиняется весь план:

> Положение подписи задаётся её датой и текущим масштабом. Ничто другое на него
> не влияет.

## Три источника прыжков в текущем коде

| Где | Что происходит | Какой прыжок |
|---|---|---|
| `lib/timeline/layout.ts:163` | `const side = x + rowWidth > width - 10 && x > width * 0.5 ? 'left' : 'right'` — сторона подписи зависит от `x`, то есть от прокрутки | Горизонтальный: у края подпись перескакивает на другую сторону точки |
| `lib/timeline/layout.ts:229–236` | `laneCount` считается по `visiblePlacements` — по тому, что сейчас на экране | Вертикальный: при прокрутке меняется высота области событий, и все подписи съезжают |
| `TimelineView.tsx` → `TimelineEventLayer` | В раскладку приходит уже отфильтрованный набор (тип события, «Вся база»), плюс отсечение по краям с запасом | Вертикальный: включение и выключение фильтра переставляет дорожки |

Четвёртый, отдельный: при выключении полос эпох строка эпох схлопывается, ось
лет уезжает вниз, и события, привязанные к оси, едут вместе с ней.

## Что делаем

### Правило 1. Раскладка — по полному набору

`buildTimelineLayout` получает **все события ленты**: без фильтра по типам, без
отсечения по краям экрана. Дорожки и стороны считаются один раз на текущий
масштаб. Фильтр перестаёт быть входом раскладки и становится свойством
отрисовки: скрытое событие сохраняет свою дорожку, просто не рисуется.

Цена решения: при выключенном фильтре в раскладке остаются «дыры» — дорожка,
занятая скрытым событием, не переиспользуется. Это сознательный размен:
устойчивость важнее плотности.

### Правило 2. Сторона подписи — всегда одна

`side` убирается из раскладки и из компонента. Подпись всегда справа от точки,
дата — за подписью. У правого края ряд просто уходит за границу и обрезается.

### Правило 3. Высота области — по всем дорожкам

`laneCount` считается по полному набору размещений, а не по видимым. Тогда
высота меняется только при изменении масштаба.

### Правило 4. Призраки не двигают прикреплённое

Чип «Вся база» добавляет на полотно элементы, которых нет в ленте. Чтобы их
появление не переставляло существующие, дорожки раздаются в два прохода:
сначала все прикреплённые элементы, затем призраки — в те дорожки, что остались
свободны. Прикреплённое при включении чипа не двигается никогда.

### Правило 5. Строка эпох держит высоту

Число дорожек эпох считается по всем эпохам ленты независимо от того, включён
показ или нет. Выключение прячет полосы, но строка сохраняет высоту — ось лет
остаётся на месте.

Цена: при выключенных эпохах под осью остаётся пустая полоса. Это видно, но
предсказуемо; альтернатива — уезжающая ось и все подписи вместе с ней.

### Правило 6. Рисуется только то, что попадает на полотно

Раскладка считает всех, **отрисовка** оставляет только те элементы, чья коробка
(точка вместе с подписью) пересекается с полотном. Это убирает 18 невидимых
кнопок из 24, которые сейчас лежат в разметке, получают фокус с клавиатуры и
озвучиваются читалками.

Важно: отсекать по коробке целиком, а не по одной точке. Событие, точка которого
ушла за левый край, а подпись ещё видна, должно рисоваться. Событие, у которого
за краем и точка, и подпись, — нет.

## Self-Review

**Покрытие требования.** «Не прыгают по вертикали» — правила 1, 3, 5.
«Не прыгают по горизонтали» — правило 2. «Не прыгают при фильтрах, включая
эпохи» — правила 1, 4, 5. «Прыжки только при масштабе» — зафиксировано тестом
(задача 1, шаг 2, пункт 6 и задача 3, шаг 1, пункт 4).

**Что не делается.** Не возвращается проверка на выход подписи за правый край —
обрезание теперь желаемое. Не меняется вид, цвета и типографика.

**Размены, принятые сознательно.** Дорожка скрытого фильтром события не
переиспользуется — лента становится выше, чем могла бы. Строка эпох сохраняет
высоту при выключенном показе — под осью остаётся пустая полоса. Оба следуют из
требования устойчивости и описаны в документации.

**Риск.** Раскладка начинает считаться по полному набору, а не по видимому: на
ленте в сотни событий это заметно тяжелее. Сейчас в самой большой ленте
31 событие — запас огромный. Если ленты вырастут до сотен, раскладку нужно будет
кэшировать по паре «масштаб + состав», и это отдельная задача.
