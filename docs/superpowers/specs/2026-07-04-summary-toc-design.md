# Оглавление статьи-саммари (Table of Contents) — дизайн

Дата: 2026-07-04
Область: страница саммари книги `app/books/[bookSlug]/summaries/page.tsx`

## Цель

На странице саммари книги добавить навигацию по разделам статьи — список
заголовков 2-го уровня (`##` → `<h2>` в теле саммари). На десктопе — липкий
список в левом рукаве с подсветкой текущей секции при скролле (scroll-spy). На
мобильном — тонкий sticky-бар с названием текущей секции, тап открывает
нижний лист (bottom-sheet) со списком.

Не дублируется на разные саммари: TOC строится по активному саммари
(`active.bodyMarkdown`), пересобирается при смене автора (страница уже
перерисовывается по `?author=`).

## Решения (согласованы)

- **Десктоп:** левый sticky-рукав, статья остаётся ~760px и уезжает в правую
  ячейку grid'а (не строго по центру вьюпорта).
- **Мобилка:** sticky-бар «≡ <текущая секция> ▾» сверху + bottom-sheet со списком.
- **Поведение:** scroll-spy через IntersectionObserver, в списке **только H2**.
- **Порог показа:** заголовков < 2 → оглавление не рендерим совсем.

## Архитектура (единицы и границы)

### 1. `lib/summary-toc.ts` (pure, тестируемая)

```
export interface TocHeading { id: string; text: string }
export function extractH2Headings(markdown: string): TocHeading[]
export function slugify(text: string): string   // экспорт для переиспользования в рендерере
```

- Извлекает заголовки уровня `##` **в порядке документа**.
- Слугификация своим `slugify` (без внешних зависимостей): lowercase, trim,
  пробелы → `-`, удаляем всё кроме `\p{L}\p{N}-` (кириллица в якоре остаётся),
  схлопываем повторные `-`. Пустой результат → запасной `section`.
- Дедуп: повторяющийся slug получает суффикс `-2`, `-3`, … (счётчик в рамках
  одного вызова `extractH2Headings`).
- **Мирит парсинг с `SummaryMarkdown`:** перед матчингом `##` вырезает
  `<details>…</details>`-блоки (их внутренние заголовки в TOC не попадают) и
  fenced-code-блоки (``` ``` ```), чтобы `##` внутри кода/спойлера не считались
  секцией. Регэксп заголовка — по началу строки: `^##\s+(.+?)\s*#*\s*$`
  (multiline), исключая `###`+.

### 2. `components/nd/SummaryMarkdown.tsx` (server, правка)

- `h2`-рендерер проставляет `id` из **того же** `slugify` с тем же счётчиком
  дедупа, что и `extractH2Headings`. Реализация: на верхнем рендере создаётся
  один сборщик slug'ов (замыкание/`useRef`-эквивалент через фабрику компонентов),
  каждый `h2` берёт следующий id в порядке эмита. Так как оба обхода идут в
  порядке документа, id в DOM и id в TOC совпадают.
  - Ограничение (осознанное): `h2` внутри `<details>` тоже проходят через
    рендерер. Чтобы счётчик не разошёлся с `extractH2Headings` (который details
    исключает), рендерер слугифицирует **из собственного текста** независимо (тот
    же алгоритм + свой дедуп-счётчик на весь top-level рендер, включая
    вложенные). Совпадение id для TOC-заголовков гарантируется тем, что top-level
    `##` идут раньше любых вложенных и в том же порядке; редкая коллизия slug
    между top-level и одноимённым заголовком внутри details закрывается дедуп-
    суффиксом — на TOC-ссылки это не влияет. Задокументировать в коде комментарием.
- Добавляет `scroll-margin-top: calc(var(--header-height, 0px) + 1rem)` на `h2`,
  чтобы якорь не уезжал под липкий [Header](components/nd/Header.tsx).

### 3. `components/nd/SummaryToc.tsx` (client, `'use client'`)

- Пропсы: `headings: TocHeading[]`.
- Один компонент, оба режима (десктоп-рукав и мобилка) внутри, переключаются
  **CSS media-query**, не JS-детектом ширины (чтобы не мигало при SSR/гидрации).
- scroll-spy: `IntersectionObserver` по всем `#id` из `headings`; активный —
  последний пересёкший верх вьюпорта (rootMargin с учётом header-height). При
  клике — плавный скролл к якорю (`scrollIntoView({behavior:'smooth'})`,
  `scroll-margin-top` уже задан в CSS), на мобилке дополнительно закрыть лист.
- Десктоп: `<nav>` со списком; активный пункт — левая линия `2px solid var(--accent)`
  + цвет `--text`.
- Мобилка: sticky-бар (текущая секция) + bottom-sheet (список H2, оверлей,
  закрытие по тапу вне/по пункту/по Esc).

### Композиция страницы

`page.tsx`:
```
const toc = extractH2Headings(active.bodyMarkdown)
```
- Оборачивает контент в grid. `toc.length >= 2` → рендерит `SummaryToc`;
  иначе — одна колонка как сейчас.
- Ключ по `active.id` (как у `SummaryArticle`), чтобы TOC пересобирался при
  смене автора.

## Верстка и адаптив

- **≥1100px:** `display:grid; grid-template-columns: minmax(200px,240px)
  minmax(0,760px); gap:3rem;` — центрируем всю группу (`margin:0 auto;
  max-width:~1040px`). Левый столбец — `<nav>` с `position:sticky;
  top:calc(var(--header-height,0px) + 1.5rem)`. Правый — существующие
  breadcrumb + `<header>` + `SummaryAuthorSwitcher` + `SummaryArticle` без
  изменений разметки.
- **<1100px:** одна колонка (как сейчас, `max-width:760`), десктоп-рукав
  `display:none`, вместо него мобильный режим `SummaryToc` (sticky-бар + sheet).

## Стиль (пергаментная тема, только токены)

- Метка «СОДЕРЖАНИЕ» — класс `t-eyebrow` (uppercase, `--text-muted`).
- Пункты — `--nd-sans`, `--text-secondary`; hover → `--text`.
- Активный пункт — `--text` + левая линия `2px solid var(--accent)` (линия, не
  заливка — правило 4 дизайн-системы).
- Острые углы (`--radius: 0`), без теней.
- Bottom-sheet: фон `--bg-input` (белый), верхняя граница `2px solid
  var(--border-strong)`, оверлей — полупрозрачный тёмный (через токен, не литерал
  — использовать существующий паттерн оверлея, если есть; иначе `--text` с
  прозрачностью через `color-mix`).

## Вне зоны (YAGNI)

- Нет H3/вложенности в списке.
- Нет «прогресс-бара чтения», нет автоскрытия рукава.
- Нет анкор-ссылок с копированием (`#` при hover) — только навигация.
- Нет URL-хэша в адресной строке при scroll-spy (только при явном клике —
  нативное поведение `scrollIntoView`; хэш не пишем, чтобы не спамить историю).
