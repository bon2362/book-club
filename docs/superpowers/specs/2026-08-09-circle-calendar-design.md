# Календарь круга: согласование времени встреч

**Дата:** 2026-08-09
**Статус:** дизайн согласован, план реализации не написан

## Задача

Участники круга должны договариваться о времени встречи внутри сайта, а не во внешнем сервисе. Прототип по функциональности — [avails](https://avails.citizeninfra.org): сетка получасовых слотов, каждый закрашивает своё свободное время, наложение показывается градацией зелёного, затем фиксируется финальный слот.

Код avails не переиспользуется. Причины: лицензия AGPL-3.0 распространилась бы на весь наш сайт; стек несовместим (React + Vite + Express против Next.js 14 + Drizzle); данные и личность в avails живут в AT Protocol и требуют аккаунта Bluesky, которого у участников клуба нет. Заимствуется только идея интерфейса, лицензией не защищённая.

## Ключевое решение: календарь глобальный, страницы — по кругам

Свободное время принадлежит **пользователю**, а не кругу. Человек может читать несколько книг одновременно и состоять в нескольких кругах; заставлять его заполнять одну и ту же сетку по разу на круг — лишняя работа.

При этом у каждого круга своя страница со своей ссылкой, где наложены календари только его участников, и своя длительность встречи. В шапке страницы — книга и состав круга.

Зафиксированная встреча вычитается из свободного времени участника **во всех** его кругах, включая тот, где она назначена.

## Привязка страницы к кругу

### Проблема

`rebuildAutomaticCircles` (`lib/matching/book-transition-db.ts:133`) при каждой новой записи на уже сформированную книгу удаляет все строки `matching_circles` этой книги и создаёт заново со свежими UUID. Прямая ссылка на `matching_circles.id` из календаря ломалась бы молча.

Состав круга при этом меняется не всегда. `partitionBookAssignments` сортирует назначения по времени записи и нарезает по `MIN_CIRCLE_SIZE=3` / `MAX_CIRCLE_SIZE=5`. Пока у книги один круг (3–5 человек), новый участник дописывается в конец и никого не перетасовывает. Перестановки начинаются с шестого человека, когда кругов становится два.

### Решение (вариант B)

Страница адресуется тройкой **сессия + книга + номер круга** (`matching_circles.position`), а не идентификатором строки. Обычная пересборка кругов не ломает ни ссылку, ни назначенные встречи. Заморозка состава в ядре matching **не вводится**.

Обоснование выбора: разделение круга на два — редкое событие, и оно в любом случае обсуждается в Telegram-чате клуба. Согласование календаря — часть этого более широкого процесса, а не изолированный автоматический флоу.

### Известные следствия

- При переходе через шесть участников состав круга меняется, а встречи остаются привязанными к номеру круга. Встречи круга №1 сохраняются, новый круг №2 начинает с пустой страницы.
- `admin_delete_book_circle` (`book-transition-db.ts:423`) удаляет круг, не перенумеровывая остальные, а последующая автоматическая пересборка нумерует круги подряд с первого. После такой пары действий номера съезжают и страница может оказаться привязана к другому составу. Случай редкий и только административный; отдельной защиты не делаем.
- Автоматическая пересборка обнуляет ручные размещения админа. Это существующее поведение matching, календарь его не меняет.

## Данные

### `user.timezone`

Новая колонка в таблице `user`: IANA-идентификатор (`Europe/Belgrade`). Nullable в схеме, но обязательна для работы с календарём — до заполнения закрашивание недоступно.

### `user_availability`

Свободное время пользователя, **интервалами**, не по клеткам:

| поле | тип | смысл |
|---|---|---|
| `id` | text PK | |
| `user_id` | text FK → `user.id`, on delete cascade | |
| `starts_at` | timestamptz | кратно 30 минутам |
| `ends_at` | timestamptz | кратно 30 минутам, строго больше `starts_at` |

Индекс по `(user_id, starts_at)`. CHECK на кратность получасу и на `ends_at > starts_at`.

Почему интервалы, а не строка на клетку: по правилам проекта каждая изменяемая таблица пишется в `audit_log` построчно триггером. Один вечерний мазок мышью — шесть получасовок, неделя закрашивания — под сотню строк на пользователя. Интервалы дают одну строку на непрерывный отрезок и держат объём журнала в разумных рамках.

Хранятся абсолютные моменты времени. Часовой пояс — только представление; переход на летнее время обрабатывается автоматически, потому что интервал привязан к точке на оси времени, а не к «19:00 по вторникам».

Записи, целиком лежащие в прошлом, удаляются при чтении состояния календаря. Отдельного cron нет.

### `circle_schedules`

Пространство согласования одного круга. Создаётся лениво, при первом заходе на страницу.

| поле | тип | смысл |
|---|---|---|
| `id` | text PK | |
| `session_id` | text FK → `matching_sessions.id`, on delete cascade | |
| `book_id` | text FK → `books.id`, on delete restrict | |
| `position` | integer | номер круга, ≥ 1 |
| `slug` | text | уникальный, адрес страницы |
| `duration_minutes` | integer | по умолчанию 60, кратно 30, ≥ 30 |

Уникальные индексы: `(session_id, book_id, position)` и `slug`.

Внешнего ключа на `matching_circles` нет намеренно — в этом суть выбранного решения.

**Как определяется состав круга.** Слаг разрешается в строку `circle_schedules`, из неё берётся тройка «сессия + книга + номер». По ней в `matching_circles` находится текущая строка круга, а по её `id` — участники из `matching_book_assignments.circle_id`. Состав вычисляется на каждый запрос и не снимается снимком: если matching пересобрал круги, страница просто покажет актуальный состав. Если круга с таким номером больше нет (книга распалась или админ удалил круг), страница показывает объяснение и уже назначенные встречи, но закрашивать и назначать новые нельзя.

### `circle_meetings`

Назначенные встречи, много на одно пространство.

| поле | тип | смысл |
|---|---|---|
| `id` | text PK | |
| `schedule_id` | text FK → `circle_schedules.id`, on delete cascade | |
| `starts_at` | timestamptz | кратно 30 минутам |
| `duration_minutes` | integer | снимок длительности на момент назначения |
| `created_by` | text FK → `user.id`, on delete set null | |
| `created_at` | timestamptz | |
| `canceled_at` | timestamptz nullable | отмена — простановка метки, не удаление |
| `canceled_by` | text FK → `user.id`, on delete set null | |

Отменённые встречи не удаляются: журнал должен показывать, кто передумал.

### Аудит

`user_availability`, `circle_schedules` и `circle_meetings` добавляются в `AUDITED_TABLES` (`lib/audit/audited-tables.ts`) и получают триггеры `audit_capture()` в той же миграции. Без этого падает контрактный тест `drizzle/0040_audit_triggers.test.ts`. Чувствительных колонок, требующих маскирования, в этих таблицах нет.

Все мутации идут через `withAuditContext`, иначе падает ESLint.

## Чистая логика

Три модуля без обращения к базе, каждый покрывается unit-тестами:

**`lib/calendar/availability-intervals.ts`** — операции над набором интервалов пользователя: добавить отрезок, убрать отрезок, слить соседние и пересекающиеся, разрезать интервал посередине. Нормализованный результат: непересекающиеся интервалы, отсортированные по началу, соседние склеены.

**`lib/calendar/overlap.ts`** — расчёт наложения. Вход: интервалы участников круга, их встречи, окно и длительность встречи. Выход по каждой получасовке: сколько участников свободно, кто именно и свободны ли все.

Отдельно вычисляется, допустима ли клетка как **начало** встречи. Это чисто календарное ограничение и оно не связано с согласием участников: начало допустимо, если встреча целиком помещается в окно 4 недель и не начинается в прошлом. Клетка, где не свободен никто, остаётся допустимым началом — согласие проверяется людьми в чате, а интерфейс лишь предупреждает.

**`lib/calendar/busy.ts`** — вычитание занятого: из свободного времени пользователя убираются все его неотменённые встречи во всех кругах, включая текущий. Возвращает не только «свободен/нет», но и причину занятости (какая книга) — для подписи владельцу слота.

## Доступ и адреса

**Адрес:** `slowreading.club/calendar/<slug>`. Слаг генерируется из названия книги транслитерацией при создании пространства; для второго и последующих кругов той же книги добавляется числовой суффикс (`zarya-vsego`, `zarya-vsego-2`). Админ может переписать слаг вручную; старый адрес при этом перестаёт работать.

**Просмотр:** без авторизации, любой по ссылке. Видны имена участников (те, что они сами выставили в профиле — многие уже скрывают настоящее имя), их часовые пояса, наложение и назначенные встречи. Индексация поисковиками не блокируется — решение владельца проекта, принято осознанно; закрыть можно позже одной строкой.

**Редактирование:** участники круга под своим аккаунтом и админ. Права вычисляются на сервере и приходят в ответе состояния.

**Админский режим:** параметр `?as=<userId>`, как на `/matching`. Доменное действие относится к просматриваемому участнику, actor и source в `audit_log` остаются административными. Сервер отклоняет `as` от неадминистратора.

## Интерфейс

### Сетка

Скользящее окно — 4 недели вперёд от сегодняшнего дня, прошедшее отваливается. Показывается по одной неделе за раз, семь колонок, переключение недель кнопками. Шаг — 30 минут.

Время рисуется в часовом поясе смотрящего: у залогиненного из профиля, у анонимного гостя из браузера с возможностью переключить. По умолчанию видна полоса примерно с 08:00 до 24:00 по местному времени смотрящего; полные сутки раскрываются отдельной кнопкой.

Закрашивание протягиванием мыши, сохранение по ходу без кнопки «сохранить». Обновление чужих изменений — при перезагрузке страницы. Realtime намеренно не делается.

### Наложение

Насыщенность зелёного пропорциональна доле свободных участников. Клетки, где свободны все участники круга, помечаются дополнительно и заметно: в отличие от avails, мы знаем точный размер круга и можем это утверждать. Наведение или тап показывает поимённо, кто свободен.

Занятые встречей получасовки не считаются свободными. Владельцу слота подписывается причина («встреча по „Заре всего“»), остальные видят только факт занятости.

### Назначение встречи

Длительность встречи хранится у круга, по умолчанию 60 минут, шаг 30 минут, меняет любой участник или админ.

Участник кликает клетку начала, видит подтверждение с итогом («сб 6 июня, 17:00–18:00, свободны 4 из 5») и подтверждает. Несогласие части круга **не блокирует** назначение, а показывается предупреждением: финальная договорённость рождается в Telegram, интерфейс её только фиксирует.

Любой участник круга и админ может отменить встречу — время сразу освобождается во всех кругах.

Сервер при назначении перепроверяет, что ни у кого из участников это время не занято другой встречей, и что слот не в прошлом.

### Несколько встреч

Круг может назначить встречу вперёд, не дожидаясь прошедшей, и назначить следующую после состоявшейся — по тому же адресу.

Раскладка страницы: сверху крупно карточки предстоящих встреч; ниже сетка, свёрнутая под кнопку «Назначить ещё встречу», если хотя бы одна предстоящая встреча уже есть; прошедшие — в свёрнутом списке «Уже прошли».

Это сознательное отступление от исходной формулировки «после финального выбора скрыть календарь». Полностью убрать сетку нельзя, иначе следующую встречу не назначить; вместо этого она сворачивается, а главным элементом экрана становится ближайшая встреча.

### Часовой пояс

Обязательное поле, собирается точечно: при первом заходе на страницу календаря показывается один экран с уже подставленным из браузера поясом, который надо подтвердить. Блокирующего экрана на остальном сайте нет. Дальше меняется в профиле.

### Точка входа

В `components/nd/MatchingBookCircles.tsx` в блоке круга добавляется ссылка «Согласовать время». Видна участникам этого круга и админу.

### Мобильная версия

Те же семь колонок, узкие, переключение недель кнопками. Протягивание пальцем конфликтует с прокруткой страницы, поэтому основной способ на телефоне — тап по клетке, а протягивание включается после долгого нажатия.

### Оформление

Только токены из `app/globals.css`, литеральных цветов и произвольных Tailwind-значений нет. Градации заполненности строятся от `--success`; «свободны все» помечается акцентной линией, а не отдельной заливкой — заливка цветом в дизайн-системе разрешена только активной кнопке и статусным CTA. Геометрия — через `--radius-card` / `--radius-control`, тени — через `--shadow-card`.

## HTTP

| метод и путь | назначение |
|---|---|
| `GET /calendar/[slug]` | страница, серверный рендер, без авторизации |
| `GET /api/calendar/[slug]` | состояние: участники, пояса, наложение, встречи, длительность, права смотрящего |
| `PUT /api/calendar/availability` | сохранение полного набора интервалов пользователя |
| `POST /api/calendar/[slug]/meetings` | назначить встречу |
| `DELETE /api/calendar/[slug]/meetings/[id]` | отменить встречу |
| `PATCH /api/calendar/[slug]` | длительность встречи; слаг — только админ |
| `PATCH /api/profile/timezone` | часовой пояс |

Все роуты, читающие внешние данные, помечаются `export const dynamic = 'force-dynamic'`.

Схема `expectedStateVersion` из matching **не переиспользуется**: календарь не входит в состояние matching, каскадных пересчётов у него нет. Защита от конкурентной правки — сохранение полного набора интервалов вместо дельты плюс серверная перепроверка занятости в момент назначения встречи.

## Миграция

`drizzle/0062_calendar.sql`: колонка `user.timezone`, три таблицы, индексы, CHECK-constraints, триггеры аудита.

Миграции проекта на production не применяются автоматически. Порядок выкатки:

1. дождаться production-деплоя PR;
2. из checkout актуального `main` выполнить `node --env-file=.env.local scripts/apply-migration.mjs drizzle/0062_calendar.sql`;
3. проверить страницу круга и вкладку Matching.

До прогона миграции страница календаря обязана отдавать понятную заглушку «функция ещё не включена», а не 500. Это отдельный пункт плана реализации.

## Тесты

**Unit обязательны** — три чистых модуля содержат условную логику над данными: склейка интервалов (включая разрез посередине и склейку встык), расчёт наложения, вычитание занятого. Плюс генерация слага с коллизиями и валидация кратности получасу.

**E2E обязательны** — новый UI-флоу и персистентное состояние. Сценарии с обязательной перезагрузкой страницы:

- закрасил время → `page.reload()` → закрашенное на месте;
- назначил встречу → `page.reload()` → встреча видна, сетка свёрнута;
- назначил встречу в одном круге → на странице второго круга это время у того же человека занято;
- отменил встречу → время снова свободно в обоих кругах;
- анонимный посетитель видит сетку, но не может её править;
- админ через `?as=` закрашивает за другого, в `audit_log` actor административный.

**Layout-тест** `e2e/calendar-layout.spec.ts` — геометрия клетки через `boundingBox()` на desktop и mobile: от размера клетки зависит попадаемость пальцем.

Перед написанием тестов обязательно читается `docs/features/testing.md`.

## Риски

**Закрашивание пальцем на мобильном.** Конфликт протягивания с прокруткой страницы. По опыту проекта такие вещи не воспроизводятся в headless Chromium и ловятся только на живом устройстве. Нужна проверка превью с телефона владельцем проекта.

**Объём сетки.** 4 недели × сутки × 30 минут — 1344 клетки. При показе по неделе и свёрнутых ночных часах на экране 7 × 32 = 224 клетки; на телефоне колонка получается узкой. Второе место, требующее живого взгляда.

**Публичная индексация.** Страница с именами участников и их графиком доступна поисковикам. Решение принято владельцем проекта осознанно.

## Явно вне объёма

- уведомления в Telegram о назначении встречи и напоминания накануне — обсуждались, решено не делать в первой версии: обсуждение и так идёт в чате круга;
- ссылка на звонок или адрес места встречи;
- realtime-обновление чужих изменений;
- повторяющиеся встречи по расписанию;
- заморозка состава круга в ядре matching.
