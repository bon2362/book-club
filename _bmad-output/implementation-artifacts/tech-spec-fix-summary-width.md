# Исправить ширину саммари без оглавления

<frozen-after-approval reason="human-owned intent — do not modify unless human renegotiates">

## Intent

**Problem:** На десктопе страница опубликованного саммари без двух заголовков `##` не рендерит оглавление, но всё равно включает двухколоночную grid-схему. Единственная контентная колонка занимает место 240-пиксельного рукава оглавления, поэтому текст становится чрезмерно узким, а справа остаётся большое пустое поле.

**Approach:** Включать десктопную двухколоночную сетку только когда оглавление действительно присутствует. Без оглавления сохранять обычную центрированную читательскую колонку шириной до 760 px; поведение страниц с оглавлением и мобильная раскладка остаются прежними.

## Boundaries & Constraints

**Always:** Использовать существующие классы и дизайн-токены; сохранить порог TOC `toc.length >= 2`, ширину читательской колонки 760 px и breakpoint 1100 px; покрыть CSS-регрессию `boundingBox()`-тестом на десктопе; не менять sticky-поведение существующего рукава.

**Ask First:** Любое изменение порога появления оглавления, ширин 240/760 px, breakpoint или визуального канона страницы.

**Never:** Не менять Markdown-рендеринг, данные саммари, мобильный TOC, типографику, цвета или пользовательские действия; не добавлять новый layout-компонент ради одного условного CSS-модификатора.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Саммари без TOC | Десктоп ≥1100 px, меньше двух `##` | Статья центрирована и занимает читательскую колонку до 760 px | Не должна попадать в 240-px TOC-слот |
| Саммари с TOC | Десктоп ≥1100 px, два и более `##` | Слева остаётся рукав 240 px, справа статья до 760 px | Существующий sticky-тест остаётся зелёным |
| Мобильная ширина | Viewport <1100 px | Сохраняется одноколоночная раскладка и текущий мобильный TOC | Десктопный модификатор не меняет мобильную геометрию |
